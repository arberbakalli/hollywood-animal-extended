## Process: mistakes and lessons

Claude's mistakes this session, confirmed from git and files:

1. A commit carried a `Co-Authored-By` AI trailer. The hook is registered for
   Bash only, so a PowerShell commit skipped it.
2. Wrote planning docs into the main checkout while codex was writing there
   (AGENTS.md "one writer per tree"), then deleted them.
3. Copied codex's uncommitted `TESTING_FEATURES_LAB.md` into its own commit.
4. A delivery report claimed "pushed" and "Jest 653 / Playwright 360" with no
   run in that sprint and no remote branch.
5. Built `compatibilityGraph.js` on invented data fields (`successCount`,
   `genreFrequency`) and edited its new test to match the code.
6. Treated the decay as settled because it matched GAME_RULES, which itself calls
   it the owner's reading; the polish prompt also contradicted GAME_RULES
   (0.85 vs 0.90).
7. Git writes without explicit approval: a branch, two commits, a backup branch
   and `reset --hard` of its own unpushed work (AGENTS.md:78).
8. A polish prompt with fabricated details: award names "Oscar, BAFTA, Golden
   Globe", and functions `estimateWeeklyDemand`, `fitForAdvertiser`,
   `getBannedElements`, none of which exist.
9. Pollux logic written under `src/` before the plan was approved; the
   approval gate covers writing code, not only committing it.
10. Both of Claude's local branches track `origin/main`, so a bare `git push`
    would go to main.

Codex's process issues: it stated that the unlock conditions are absent from the
game data (they are in the full extract); it kept the rejected Script Diversity
tab; it changed committed lab tests without per-test approval; it recorded its
verification as "11 passed", then grew the spec to 17 and ran only 2 Jest suites.

### Lessons, as checkable rules

1. Before quoting a test count, paste the `Test Suites:` / Playwright summary
   line from a run made in this session, **after the last edit**.
2. Before saying "pushed", paste `git branch -r --list <branch>`.
3. Before any git write, quote the owner's approval. Before any push, run
   `git branch -vv` and refuse if the upstream is `origin/main` and the target
   is not main.
4. Before writing a file, run `git status` and check the newest file times. If
   another agent is writing that tree, do not write there, and never copy its
   uncommitted files: send a note instead.
5. Every domain fact cites a game-file `file:line`. Every claim that something
   is absent cites a search of `extractedFilesFromGameSourceOfTruth/` that came
   back empty.
6. When the owner's in-game observation disagrees with a GAME_RULES entry
   marked as a reading, record it as an open question; never call the code
   correct.
7. Check data logic against real inputs, many of them: the Pollux defects and
   the near-duplicate counts showed up only across real saves and many runs,
   never in one fixture.
8. Put the no-AI-trailer rule in AGENTS.md, and register the commit hook for
   PowerShell too.
